# PaperOrganization 可视化方向与规则

**更新日期：2026-11-05。状态：正式可视化约束；`ToolsPy` 导出器和运行示例均应遵守。**

本文件记录未来论文图与论点图的共同视觉语义。数据定义仍以 [] 为准；可视化只读取知识库，不反写关系或证据。`ExamplePy/tree_model.html` 是依据本文件制作的第二轮造型试验；`ExamplePy/kb_visualization.html` 是早期多视图原型，二者都不是正式产品。

## 1. 总体意象与信息边界

整体采用**可旋转的 3D 时间树**意象：论文节点构成深色“树干/枝”，论点像挂在论文旁的浅色“铃铛”，论点关系像铃铛之间的彩带。这里的“树”是视觉隐喻，**不能把数据伪装成严格的树**：论文引用和脉络可能一篇对应多个前驱、形成交叉边，也可能互不相连。无真实关系时不画虚构枝条。

两层索引图同时可见，但有清楚的层级：

| 对象 | 默认外观 | 作用 |
|---|---|---|
| 论文节点 `papers` | 深色、有体积感的圆柱/多面体核心 | 时间叙事的主要骨架；标签默认优先显示 |
| 论文间脉络 `paper_relations` | 较粗的定向枝状线 | 表示经阅读推断的继承、派生或汇合 |
| 原始引用 `citations` | 更细的定向线，默认可关闭 | 表示“引用了”，不能冒充“继承了” |
| 论文→论点所属关系 | 浅色、短而细的“挂线” | 表示 `claims.paper_id` 所属；不是引用或推理关系 |
| 论点节点 `claims` | 浅色的菱形、铃铛或小立方体；与论文节点轮廓不同 | 表示可寻址主张，形状不能与论文混淆 |
| 论点关系 `claim_relations` | 有颜色、弯曲且带方向提示的“彩带” | 表示 support / contradict / extend / use |

默认场景背景宜使用中性深色，保证深色论文节点仍有足够亮度差、边缘光和可读标签；“深色论文/浅色论点”是**对象配色**，不要求整个界面始终深色。适配浅色/深色系统主题，但对象类型的明暗关系保持不变。颜色之外必须有形状、线型、箭头或文字图例区分。

## 2. 空间排布：时间轴 + 关系方向

**时间轴固定在竖直方向并遵循阅读顺序**：越早的论文越靠上，越晚越靠下。画面中心必须有一条持续可见的时间主轴，轴上标出真实年份；节点从较窄的早期层向较宽的晚期层展开，形成清楚但不伪造关系的“圣诞树”轮廓。默认用 `papers.year`；`preprint_year` 若不同，以次级刻度/标记显示，避免把预印本年与发表年混为一谈。年份缺失的论文放入明确标注的“年份未知”带，不自行推断。时间间距应按年份差计算，长空档可压缩但必须在轴上说明。

**时间参照平面**：在有论文的年份高度放置非常浅的半透明水平平面，并在平面边缘标注年份。平面要能随镜头旋转正确投影，提供明显的前后空间参照，但不能盖住节点、边和标签；透明度、网格线及平面数量随缩放级别调整。时间平面是辅助刻度，不编码论文数量、质量或关系强度。

同年论文在水平环/扇区内排布。论文关系约束水平位置：有真实引文或脉络关系的论文尽量在相近扇区，让路径沿时间轴上升；无关系的论文仍占独立位置。越晚年份可逐渐增大可用半径，形成**松散锥形树冠**，但半径只服务避免重叠，不应被解释为质量、影响力或引用数。布局应固定随机种子或确定性排序，让重开页面时同一节点位置稳定。

论文关系是图而非树：多前驱保留多条边，交叉边允许弯曲绕行；不强行挑一个“父节点”。论文“引申”的论点围绕所属论文生成局部簇，位置与论文年份相近，不能看起来像另一篇更晚的论文。跨论文论点关系在外围走弧线，避免穿过论文核心骨架。

**关系方向必须区分存储方向与画面方向。** `paper_relations` 文档中 `src_paper` 是较晚的继承者、`dst_paper` 是较早的前驱；画面时间箭头应从前驱指向继承者。`citations.from_paper → to_paper` 是引用者指向被引者，若展示原始引用箭头，应保持引用语义并在图例说明，不能悄悄反转。`claim_relations.src_claim → dst_claim` 按记录方向展示；论点关系的逻辑意义不能仅凭年份解释。

## 3. 节点与边的视觉编码

节点类型首先靠**轮廓**区别：论文为稳定、厚重的实体；论点为轻量菱形/铃铛；将来若展示 `assumptions`、`media`，必须使用新的形状并默认折叠，不把它们误当论点。节点大小不直接绑定引用数，除非用户主动选择该编码并看到比例图例。`reading_depth` 可用小型外环/标记表示，不能改变论文或论点的基本形状。

边的类型与语义要同时可辨：

| 边 | 默认视觉建议 | 点击后必显示 |
|---|---|---|
| 论文脉络 | 深蓝/青色实线、较粗、带箭头 | `kind`、`axis`、`evidence`、`confidence`、`generated_by` |
| 原始引用 | 低饱和细线，可切换显示 | 来源 `source` 与双方论文 |
| 论文→论点 | 浅灰/浅金短线，无语义箭头 | 所属论文、论点摘要 |
| `support` | 绿色实弧 | 两端论点、极性、证据、置信度 |
| `contradict` | 红/橙色实弧；高亮时按级别改虚线 | 同上 |
| `extend` | 紫色带箭头弧 | 同上 |
| `use` | 蓝绿色点划弧 | 同上 |

颜色是建议色系，不是唯一识别方式。`kind` 与 `polarity` 是两个独立字段，不能仅凭边色推断极性；边详情和图例须同时展示两者。置信度可影响透明度，但低置信度边仍可在聚焦时看见。证据缺失、无法解析、来自模拟数据等状态必须明显标识，不能用同样的实线外观伪装为已验证关系。

**默认边线一律为实线**，通过颜色、粗细、箭头和明确的图例区分关系类型；数据来源或真实性需要独立标识，不能依赖虚线与否。除论文间边以外，论文→论点挂线和论点关系在未选中状态下也须可见；其中论点间关系应比论文主干更柔和，不能抢走视觉焦点，选中后再增强。跨论文的论点关系优先沿树冠外缘走弧线，减少穿过论文骨架的遮挡；论点节点靠近所属论文节点，论文节点默认尺寸应较小。

## 4. 3D 交互与三级邻域高亮

支持鼠标/触控旋转、缩放、平移；提供“重置视角”“沿时间轴查看”“聚焦当前对象”和“返回全图”。视图左侧必须提供纵向位置滑条，使用户在放大后无需反复 Shift 拖动即可沿时间轴上下移动。旋转时年份轴与朝向提示持续可见，避免用户失去时间方向。点击节点、边都能打开固定详情区；悬停只显示简短标签，不承担唯一的信息入口。重叠时优先选取离镜头最近的对象，并允许在详情区选择被遮挡的相邻对象。

论点模式不得让论点失去论文上下文：论文节点以较弱样式保留，选择论点时，所属论文通过 ownership 边进入最高或相邻高亮级别，并显示论文标签。

提供可停止的**时间演示模式**：从最早年份开始，按时间顺序依次显示该年的论文、所属论点以及两端都已出现的关系，直至当前快照完整呈现。播放按钮必须能中途停止；播放结束后保留完整图。演示仅改变显隐，不修改知识库、关系状态或时间字段；系统要求减少动态效果时不应自动播放。

选中对象后在**可见的类型化图**上做广度优先遍历，计算最短边数 `d`。默认规则如下，支持用户切换“仅论文图 / 仅论点图 / 两层联动”，并在图例说明当前纳入哪些边：

| 距离 | 高亮级别 | 节点与边的效果 |
|---|---|---|
| `d = 0` | 三度 | 选中对象最亮、放大最多、镜头平滑居中；选中边使用粗虚线，线段间空白最短，若选中边则两端共同进入焦点 |
| `d = 1` | 两度 | 相邻节点明显高亮、适度放大；连接边使用中等粗细的虚线，空白间隔居中 |
| `d = 2` | 一度 | 再相邻对象轻度高亮、略放大；连接边使用较细的虚线，空白间隔最长 |
| `d ≥ 3` 或无关 | 背景 | 降低亮度/透明度，不在默认情况下删除 |

边的高亮级别取其两端与焦点的关系：焦点边本身三级，连到焦点的一跳边二级，连接一跳与二跳的边一级。三级高亮的**实线线段长度相同**，只调整线段间空白：高亮越强，空白越短、越接近实线；三档都保留可辨认的空白。当前试验参数为每段 **9px**，三度/两度/一度的空白分别为 **1px / 11px / 25px**，线宽分别为 **5px / 3.4px / 1.9px**；三级高亮应几乎像实线，但仍保留细小间隔，三档保持明显区别。若某条边因类型过滤被隐藏，它不参与距离计算。不同图层的“属于”边是否参与遍历由当前模式决定；避免用户选中一篇论文后把整篇的所有论点关系一次性点亮到不可读。放大幅度建议有限（如约 1.0/1.25/1.5 倍），主要靠亮度、描边与景深体现层级，避免被放大的节点遮住其他对象。动画应平滑且尊重系统的减少动态效果设置。

点击对象后的详情遵循“论文/论点/关系 → evidence ID → 原文 span 或图表定位”。关系详情必须显示真实来源和生成者；不要只呈现漂亮的边。论点、假设、图表的细节可在详情区展开，不必全部常驻 3D 场景。

## 5. 当前数据约束与正确展示

`ExamplePy/kb/index.sqlite` 在 2026-10-09 的检查结果：15 篇论文、14 条论点关系、**0 条 `paper_relations`**；14 条论点关系均为 `extend`。134 条 `citations` 使用外部标识作被引端点，当前示例库没有可直接连接的库内论文引用边。阅读结果来自模拟 PaperRead。由此，现阶段无法忠实展示“论文引用组成的 3D 树”或比较多种真实论点关系颜色。

原型必须如实保留这种稀疏状态：展示时间骨架与论文节点、论文所挂的论点，并提示论文脉络尚未生成。为了试验视觉效果可以增加**明确标为演示数据**的临时边，但演示边不可写回知识库，也不可与真实关系使用相同图例。正式产品应先补足库内引用映射、跨论文脉络与真实阅读关系，再评价整体树形是否成立。

## 6. 实现研究与分阶段验收

建议采取**时间轴约束的 3D 图布局**，而非纯随机力导向图：固定年份坐标，在每个年份层内通过关系吸引、碰撞排斥和稳定排序安排论文；论点簇再附着到论文节点。可先在 `ExamplePy` 做数据导出和布局试验，验证交叉边、孤立节点、不同年份密度；正式实现再移入 `ToolsPy`。`3d-force-graph` 提供 DAG 约束、定制节点、边样式、点击与相机控制等能力；若其约束不足，可直接用 Three.js 自定义布局、对象与拾取。后者更灵活，但需要自己处理镜头、标签遮挡和选中判定。[3d-force-graph 文档](https://github.com/vasturiano/3d-force-graph/blob/master/README.md)、[Three.js Raycaster 文档](https://threejs.org/docs/pages/Raycaster.html)。

分阶段验收：

1. **语义正确**：同一数据重复布局稳定；时间坐标和两种方向关系正确；孤立论文没有假枝条；无证据边有明显状态。
2. **视觉可读**：深色论文与浅色论点一眼可分；至少四种论点边可同时用颜色和线型区分；正视、侧视及旋转后年份方向仍可识别。
3. **交互完整**：点击节点/边均可打开详情；三级邻域高亮准确；过滤后重新计算邻域；隐藏的边不被误选；可回到全图。
4. **数据扩展**：用小、中、大三档合成数据试验遮挡与性能；真实数据保持单独标记。先实现聚合、局部展开和标签按需显示，再考虑大图全量渲染。
5. **人工任务验证**：让使用者完成“找一篇论文的前驱”“找支持/反驳某论点的关系”“从边回到原文”三项任务，比单纯评价是否像圣诞树更能检验可用性。

## 7. 参考与设计取舍

- [Obsidian Graph View](https://obsidian.md/help/plugins/graph) 的局部图、深度控制和过滤支持“从焦点逐层展开”的交互方向。
- [Kumu Network Mapping](https://kumu.io/markets/network-mapping) 强调按连接类型过滤与聚焦个别元素；本设计借鉴其渐进探索方式。
- [Neo4j Bloom](https://neo4j.com/docs/bloom-user-guide/current/) 展示图对象详情与交互探索；本设计要求边也必须能进入证据详情。
- [3d-force-graph 的 DAG/tree 示例与 API](https://github.com/vasturiano/3d-force-graph/blob/master/README.md) 表明 3D 定向布局和节点、边点击可实现；但本项目的年份坐标和两层语义需要额外约束，不能直接套示例布局。

**设计结论**：保留“圣诞树”作为易懂的整体意象，但以时间、真实关系和证据为优先约束；视觉层次不能制造知识库里没有的推断。
